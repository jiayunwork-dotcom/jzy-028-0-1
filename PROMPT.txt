距离向上每个分辨单元要不要报目标，得看它两侧参考窗里的均值，而不是拿一个全局门限套整条线。调用方交出一条非负幅度序列，以及保护单元数、每侧参考单元数和虚警率 Pfa。服务从左到右滑过每一个被测单元（CUT）：紧邻 CUT 的保护单元不进均值，再往外两侧各取规定个数的参考单元，用它们的平均幅度乘以由 Pfa 和参考总数决定的因子 α，得到该 CUT 的阈值；幅度超过阈值则检出。范围限定在单元平均恒虚警检测，仅经 HTTP 提交距离线并取回逐单元阈值与检出标记。

对指数或瑞利包络，α 钉死为 N 乘以（Pfa 的 −1/N 次方再减 1），N 是两侧参考单元个数之和。α 必须随 Pfa 和 N 变，禁止写成与 N 无关的常数。Pfa 必须落在 0 与 1 的开区间。保护单元数、每侧参考数必须是非负整数，且每侧参考数至少为 1。幅度不得为负。窗长为 0（没有参考）拒绝。

CUT 自己以及保护单元不得进入参考均值——把目标算进均值会把该处阈值抬死，强目标反而漏检，这是必须用合成数据卡住的实现错误。靠近两端的 CUT 若某一侧参考凑不齐，该单元标为无效，不检出，也不许用零去填缺失的参考再假装做完。整条线的窗几何（保护、每侧参考、Pfa）可以登记成具名窗规，提交距离线时点名一规；也可以把三个数写在当次请求里。

只把 Pfa 降一个数量级、窗几何其余不动，α 必须升高，同样一条带目标的距离线上检出应变少。只把目标所在 CUT 的幅度加大，该单元相对阈值的裕量必须升高。在均匀噪声、无注入目标的长序列上，检出比例应落在 Pfa 附近的钉死波动带内，不要少一个数量级还声称恒虚警。中间埋一个远高于噪声的强目标时，该 CUT 必须检出，其保护单元不得仅仅因为沾边就被全部标成目标。

提交一条距离线即完成一趟滑窗：返回与输入等长的阈值、检出布尔、无效布尔，以及本趟实际使用的 α 与 N。点到未登记的窗规名字拒绝。缺项、Pfa 越界、负幅度、参考不足还去检的实现，都视为失败。滑窗的累计和只服务当前这一趟，算完清掉。

用 Node.js 20 与 NestJS 对外提供 HTTP。窗规启动时载入、运行期可追加到内存，不落库。镜像用 node:20-slim，构建后单容器启动。参考窗切片、α 计算、逐单元判决、窗规存取分开写，不要进同一个文件。测试覆盖：α 随 Pfa 与 N 变化且符合钉死公式、强目标被检出、保护单元未抬高目标处阈值、边缘参考不足标无效而不是补零、Pfa 降一个数量级则 α 升高且检出变少、均匀噪声经验虚警落在波动带、负幅度被拒、Pfa 越界被拒、未知窗规被拒。
